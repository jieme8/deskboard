六种状态

默认就是你这台机器的形态：内建电池 80%、交流电、未充电，右边三格空环。空槽、未知、无电池都和真实读数分开。

  • 点击：有设备的环打开对应系统设置；按住移动超过 3pt 仍是拖组件。
  • 采样：本机 30s、Magic 外设 60s、AirPods 120s；插拔电源立即刷新，隐藏时暂停。
  • 不做：充电上限/充电管理没有公开 API，只提供「打开电池设置」深链，不画假开关。

和数据源的对应

能读到的进环，读不到就留空；所有「未知」都印「—」，不印 0。

  • 内建电池：复用 DeskStats 的 IOPS 读数（百分比 / 交流电 / 充电 / 充满 / 剩余分钟），健康度走 AppleSmartBattery（设计容量、循环次数、温度）。本机实测 80% · 交流电 · 未充电。
  • Magic 外设：IORegistry AppleDeviceManagementHIDEventService 的 BatteryPercent，60 秒一采，零权限。
  • AirPods：system_profiler -json SPBluetoothDataType 后台 120 秒一采，解析左/右/盒；解析失败只影响这一环，不影响其余三个。
  • iPhone / Apple Watch：原生组件走 Continuity/iCloud 私有通道，没有公开接口；本方案不做，也不画假数据。
  • 顺序：内建电池 → AirPods → 蓝牙耳机 → Magic Mouse → Magic Keyboard → Magic Trackpad → 其他 HID；超过 4 个取前 4，悬停提示「还有 N 个」。

改动落点

设计确认后再动代码；下面是这次会碰到的文件。

  • battery.h / .m — 设备模型、优先级、内建电池健康度、Magic 外设与 AirPods provider。
  • battery_view.h / .m — 364 × 140 四环绘制、档位颜色、空槽/未知、悬停气泡、点击设置。
  • main.m — 第五块窗口组、菜单、BatteryPlaces、锁定、屏幕变更、点击/拖动。
  • places.h — 新增 DeskPlaceKindBattery，默认右上 + dy 174。
  • tools/preview_battery.m — 离线输出六种状态 × 四档外观。
  • tools/verify_battery.m — 四槽等宽、环径/线宽、百分比居中、档位阈值、未知印「—」、优先级截断。
  • tools/dump_window.m — 按 364 × 140 识别电池窗，和 272 × 142 / 560 × 330 区分。
  • build.sh / README.md — 编译清单、组件说明、菜单表。
验收底线：本机真机必须出「1 个绿环 80% + 3 个空环」，和参考图同构；电量变化只补弧，不做常驻动画。
老卡片先不动：系统状态卡表尾的电池文字暂时保留，避免牵动已验证版面；新组件跑稳后再单独讨论要不要撤掉，免得同一块屏两处各写一个电池数。
